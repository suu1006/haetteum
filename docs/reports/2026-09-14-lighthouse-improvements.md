## 검증

- 웹 전체: 85개 파일, 703개 테스트 통과.
- API 인증: 14개 suite, 131개 테스트 통과. 변경 API 파일 lint 통과.
- 웹 ESLint: 오류 0. 기존 login-screen 미사용 항목 2개와 otp-code-input 불필요 disable 1개 경고 유지.
- API 빌드 및 웹 Webpack 프로덕션 빌드 통과. 기본 Turbopack은 이 실행 환경의 포트 바인딩 제한으로 실패했다. 운영 기본 빌드 파이프라인 검증은 별도 필요.
- 실제 HTTP: 익명 /auth/session 200, JSON null, private/no-store. 보호된 /auth/me 401.
- 실제 Chrome: 미리보기 초기 iframe 0 → 클릭 후 영상 재생 1 → 정지 후 0, sitemap 200 확인.
- 별도 리뷰어의 인증 null-body 직렬화 지적 반영 후 재리뷰에서 추가 actionable issue 없음.
- TourAPI 수집 및 DB 마이그레이션 실행 없음. 로컬 API의 모든 수집 스케줄러는 비활성화해 검증.

## 측정 조건과 한계

Lighthouse 13.4.1, headless Chrome, 기본 모바일 simulated throttling. 변경 후 로컬 standalone(Webpack)과 변경 전 HEAD 8c4cbe7e550a5c6906ae55baa282589cb368afb5를 임시 스냅샷으로 빌드해 비교한다. 같은 localhost:3100, 로컬 API:4100, 동일 설정의 DB 및 주간 이미지 경로를 사용한다. 별도 브라우저 프로필로 순차 측정한다.

앞선 운영 서버(Turbopack/HTTPS/다른 캐시·데이터 상태) 결과와 로컬 점수는 직접 비교할 수 없다. 로컬 재측정에서도 FCP/LCP 변동 및 잔여 CSS 렌더 차단이 있으므로, 전송량 감소·초기 CLS 제거를 확인한 것과 성능 점수 목표 달성을 구분해야 한다. 실사용 INP는 이 navigation 검사로 입증하지 못한다.

앱/인프라는 운영에 배포하지 않았다. API와 프런트를 함께 배포한 뒤 동일 운영 조건에서 반복 검사하고 HTTP/2 적용을 확인해야 한다. Web Vitals 로그가 쌓인 뒤 경로별 p75를 집계한다. 상세 URL 전체 sitemap은 현재 공개 목록 조회 API가 별도로 없어 안정적인 진입점 두 개만 등록했다.

원본 HTML/JSON: artifacts/lighthouse/2026-09-14/{baseline-local,after}/. 최초 중간 탐색 결과 중 전체 테스트와 겹친 실행은 최종 비교에서 제외한다.
