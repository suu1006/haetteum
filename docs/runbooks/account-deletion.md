# 회원탈퇴

## 사용자 흐름

마이페이지의 로그아웃 바로 아래 `회원탈퇴` → 확인 모달 → 최종 `회원탈퇴`.

- 제목: `탈퇴하시겠습니까?`
- 본문: `회원 탈퇴 시 모든 개인정보가 삭제됩니다. 정말로 탈퇴하시겠어요?`
- 취소하면 요청하지 않는다. 처리 중에는 중복 요청과 모달 닫기를 막는다.
- 성공하면 로그인 상태와 React Query 캐시를 지우고 홈으로 이동한다.
- 실패하면 계정을 유지하고 모달 안에서 다시 시도할 수 있다.

## API 및 삭제 대상

`DELETE /api/v1/auth/account`, JSON `{ "confirmed": true }`, 성공 `204`.
세션 인증과 SameOriginGuard를 적용하며 대상 ID는 로그인 세션에서만 가져온다.

사용자 행을 잠근 뒤 아래 항목을 하나의 DB 트랜잭션으로 삭제한다.

- 계정 식별자, 이름, 이메일, 비밀번호 해시, 프로필 URL·관심 지역·여행 성향
- 모든 기기의 세션
- 후기·후기 사진 연결과 소유한 업로드 사진 원본 바이트(미첨부·이전 사진 포함)
- 찜, 저장 코스·경유지, 채팅 대화·메시지
- `chat_requests`의 응답·요청 해시와 `chat_daily_usage`의 사용자별 집계
- 신고자가 본인인 신고, 작성자가 본인인 신고 스냅샷(이미 삭제된 후기의 스냅샷 포함)
- 차단·차단당한 관계, 동일 이메일의 가입 인증 대기 정보

다른 사용자 계정과 관광 데이터는 삭제하지 않는다. 일반 후기 삭제 시 스냅샷을 보존하는 기존 정책과 달리 **회원탈퇴 시에는 해당 회원의 스냅샷도 삭제**한다.

연결된 레거시 `/uploads/reviews/`, `/uploads/profile-photos/` 파일은 허용된 원본 도메인·UUID 파일명만 로컬에서 제거한다. 파일이 이미 없으면 계속 진행하고, 권한 오류 등으로 지울 수 없으면 탈퇴 성공을 반환하지 않는다. 파일 삭제는 DB 롤백으로 되돌릴 수 없으므로 이후 DB 오류가 나면 계정은 유지되지만 일부 레거시 사진은 없어질 수 있다. 재시도 시 없는 파일은 허용한다.

진행 중인 채팅이 삭제된 대화를 참조해 다시 저장하지 못하도록 `chat_requests.conversation_id`에 삭제 전파 FK를 둔다.

## 배포

1. API 배포 전에 `pnpm --filter @haetteum/api db:deploy`로 `20260915020000_account_deletion_chat_integrity`를 적용한다. 마이그레이션은 이미 없는 대화를 가리키는 고아 요청 캐시를 제거하고 FK를 추가한다.
2. API와 웹을 함께 배포한다. 업로드 사진은 `private, no-store`로 제공하고 웹은 해당 사진의 Next Image 최적화를 우회한다. 업로드 사진 URL은 원격 최적화 허용 목록에서도 제거한다.
3. 기존 Next 이미지 캐시·프록시/CDN의 사용자 사진 캐시를 운영 절차에 따라 비운다. 이 변경 이전에 다른 브라우저에 저장된 사본을 서버가 원격 삭제할 수는 없다.
4. API 실행 환경에서 기존 업로드 디렉터리가 동일한 공유 저장소를 가리키며 파일 삭제 권한이 있는지 확인한다.

## 삭제 보장의 경계와 출시 전 운영 작업

이 API의 삭제 범위는 **현재 서비스 DB와 소유권을 확인할 수 있는 연결된 레거시 파일**이다. 아래 저장소는 별도 운영 작업이 필요하며, API 성공을 해당 저장소의 즉시 삭제 증거로 사용하지 않는다.

- 배포 백업·스냅샷: 현재 배포 백업은 최근 3개 보존 방식으로 탈퇴 시 즉시 지워지지 않는다. 개인정보 처리방침에 보관 기한과 접근 제한을 확정하고, 복구 시 탈퇴 데이터가 되살아나지 않는 절차를 갖춘다.
- 예전 업로드 중 DB 연결이 이미 사라진 파일: 소유자를 복원할 자료가 없으면 계정별 식별이 불가능하다. 소유권 조사 후 불필요한 고아 파일을 별도 정리한다.
- SMTP·AI 제공자·카카오 등 외부 서비스 기록과 기존 로그: 본 API가 원격으로 삭제하지 않는다. 해당 제공자의 보관 설정·삭제 절차 및 로그 만료 정책을 확인한다. 카카오 계정 자체를 삭제하거나 카카오 서비스 이용 동의를 해제하는 API는 이 기능에 포함하지 않는다.

사용자에게 표시하는 전체 개인정보 삭제 안내를 실제 운영에서도 충족하려면 위 백업·로그·외부 보관 범위까지 정리해야 한다. 이번 구현·테스트에서 실제 사용자 탈퇴나 운영 DB 마이그레이션은 실행하지 않는다.

## 검증

`apps/api/test/account-deletion.e2e-spec.ts`는 로컬 호스트의 `haetteum_tourapi_test_`로 시작하는 일회용 DB만 허용한다. 세션·Origin·확인값 검증, 연결 데이터와 스냅샷 제거, 다른 사용자 보존, DB 오류 롤백, 모든 세션 무효화, 사진 404 및 no-store, 늦은 채팅 재저장 방지, 레거시 파일 삭제·실패를 검사한다.

`apps/web/tests/unit/features/profile/components/account-withdrawal.test.tsx`는 취소 시 무요청, 확인 전 미삭제, 처리 중 중복 클릭 차단, 성공 후 인증·쿼리 캐시 초기화, 실패 후 재시도를 검사한다.

2026-09-15 검증: 웹 단위 720개, API 단위 673개, 계약 단위 51개 통과. 전체 PostgreSQL 통합 17개 suite / 117개 테스트 통과(회원탈퇴 5개 포함). API·웹 빌드 통과. 전체 린트 오류 0개, 기존 웹 경고 3개. API 단위 테스트는 생성 파일 갱신과 분리해 단독 재실행했고, 전체 통합 테스트의 일시적 HTTP 실패 1건은 재실행에서 모두 통과했다. 검증용 PostgreSQL 컨테이너는 정리했다.
