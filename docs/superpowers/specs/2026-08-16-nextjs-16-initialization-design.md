# Next.js 16 프로젝트 초기화 설계

## 목표

빈 Git 저장소를 pnpm 기반 Next.js 16 App Router 프로젝트로 초기화한다. 초기 상태에서 개발 서버 실행, ESLint 검사, 프로덕션 빌드가 성공해야 한다.

## 기술 구성

- Next.js 16의 최신 패치 버전과 호환되는 React 버전을 사용한다.
- 패키지 관리자는 pnpm을 사용하고 `pnpm-lock.yaml`을 저장한다.
- TypeScript와 App Router를 사용한다.
- 애플리케이션 소스는 `src/` 아래에 둔다.
- Tailwind CSS와 ESLint를 활성화한다.
- import alias는 `@/*`로 설정한다.
- 실험적 옵션은 추가하지 않는다.

## 프로젝트 구조

- `src/app/layout.tsx`: 전역 레이아웃과 문서 메타데이터
- `src/app/page.tsx`: 의존성 없이 렌더링되는 간단한 시작 화면
- `src/app/globals.css`: Tailwind CSS 진입점과 최소 전역 스타일
- 루트 설정 파일: Next.js, TypeScript, PostCSS, ESLint 설정
- `public/`: 정적 자산 디렉터리

초기 화면은 기능이나 제품 도메인을 가정하지 않는다. 이후 개발을 방해하는 데모 로직과 불필요한 UI 라이브러리는 포함하지 않는다.

## 초기화 방식

공식 `create-next-app@16`을 현재 디렉터리에 비대화형 플래그로 실행한다. 공식 생성 결과를 기준으로 하되, 기본 예제 화면은 범용 시작 화면으로 단순화하고 Node.js 최소 요구 버전을 `package.json`에 명시한다.

수동 구성은 공식 기본값 누락 가능성이 있어 사용하지 않는다. 별도 스타터 템플릿은 현재 요구 범위를 넘어서는 의존성과 규칙을 가져올 수 있어 사용하지 않는다.

## 실행과 검증

- `pnpm dev`: 로컬 개발 서버 실행
- `pnpm lint`: ESLint 검사
- `pnpm build`: 프로덕션 빌드

검증은 의존성 설치 후 ESLint와 프로덕션 빌드를 실행한다. 개발 서버는 기동 및 HTTP 응답을 확인한 뒤 종료한다.

## 오류 처리와 범위

설치 또는 빌드 실패 시 실패한 명령과 원인을 확인하고 초기화 범위 안에서 수정한다. 테스트 프레임워크, 포매터, Git 훅, UI 컴포넌트 라이브러리, 인증, 데이터베이스는 이번 초기화에 포함하지 않는다.
